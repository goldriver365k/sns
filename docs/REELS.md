# AI 자동 릴스 — 개발 문서

기존 SNSROOM에 추가한 메뉴. 주제·대본·사진·영상으로 1080×1920 세로 릴스를 구성한다.
기존 기능·디자인은 그대로 두고 `src/reels/`, `src/components/reels/`, `src/pages/reels/`에만 추가했다.

## 1단계 (완료) — 메뉴, 제작 화면, 업로드, 타임라인, 디자인 5종, 모션그래픽 미리보기

| 기능 | 상태 | 비고 |
| --- | --- | --- |
| 왼쪽 메뉴 "AI 자동 릴스" + 위쪽 탭(자동 릴스 / 내 프로젝트 / 디자인 / 설정) | 완료 | 내 프로젝트·설정 탭은 "다음 단계" 안내만 표시 |

| 모션그래픽: 반짝임·불꽃·강조 박스·가격표·CTA 버튼·로고 등장·캐릭터 등장 | 완료 | 장면별로 켜고 끔. 효과 위치는 장면 id로 고정(매번 같은 그림) |
| 타임라인: 길이 비율 칸, 눌러서 이동, 끌어서 순서 변경, 재생 위치 막대 | 완료 | 모바일은 ◀ ▶ 버튼으로 순서 변경 |

### 화면 그리기 구조
- `src/reels/render.ts`의 `drawReelFrame(ctx, project, t)` — **t초의 화면을 시간만으로 그린다**(난수도 장면 id로 고정). 그래서 다음 단계 MP4 제작 때 같은 함수로 프레임을 하나씩 뽑으면 미리보기와 같은 영상이 된다.
- 미리보기는 1080×1920 캔버스를 화면에 맞춰 줄여 보여 준다. 영상 자료는 지금 장면일 때만 재생 위치를 맞춰 돌린다(소리 없음).

### 아직 없는 것 (화면에 "다음 단계"로만 안내, 작동하는 척하지 않음)
(1단계 당시) — 이후 단계에서 모두 완료: 프로젝트 저장 3단계, AI 대본 4단계, 목소리·음악·자막 동기화 5단계.

## 2단계 (완료) — MP4 제작·다운로드 (사용자 PC에서 처리)

- 오른쪽 **MP4 만들기**: 1080×1920, 30fps, 선택한 길이(10·15·30·60초). 진행 막대·취소 → 완성 영상 바로 재생 → [MP4 다운로드], 휴대폰은 [휴대폰에 저장·공유].
- 방식: 미리보기와 같은 `drawReelFrame`으로 한 프레임씩 그려 브라우저 WebCodecs로 인코딩, `mp4-muxer`로 MP4 포장(`src/reels/exporter.ts`). 서버로 보내지 않음 → 서버 비용 0.
- 코덱: **H.264를 먼저**(High → Main → Baseline). H.264 인코딩이 없는 브라우저는 VP9 방식 MP4로 만들고 경고를 보여 준다. 둘 다 안 되면 "PC의 크롬·엣지에서 열어 주세요" 안내.
- 영상 자료는 프레임마다 정확한 위치로 맞춘 뒤 그린다. 만드는 동안 미리보기는 영상 위치를 건드리지 않는다.
- 지금은 소리 없는 영상(목소리·음악은 다음 단계).
- 테스트(이 개발 환경의 브라우저는 H.264 인코딩이 없어 VP9로 확인): 10초 릴스(사진·영상·로고·반짝임·가격표·CTA) → 18초 만에 6MB MP4, ffprobe로 1080×1920·30fps·300프레임·10.0초 확인. 같은 시각의 미리보기와 MP4 프레임 평균 차이 약 2/255(압축 차이). 취소 동작 확인. **H.264 결과물은 실제 크롬·엣지에서 확인 필요.**

## 3단계 (완료) — 프로젝트 자동 저장·다시 편집

영상 저장 방식은 사용자가 **"이 기기 브라우저 안에 저장(무료)"**으로 결정(2026-10-21). 유료 서비스 없음.

| 무엇 | 어디에 | 다른 기기에서 |
| --- | --- | --- |
| 제목·주제·대본·장면·길이·디자인·로고 지정 | Firestore `reelProjects/{id}` | 보임 |
| 목록용 작은 미리보기 그림 | 같은 문서 `thumbnail` | 보임 |
| 사진·로고·캐릭터 | 이 기기 IndexedDB(원본, 긴 변 2160px) + Firestore `images`(긴 변 1600px 이하, 투명 배경 유지) | 보임(1600px 판) |
| 영상 | 이 기기 IndexedDB만 | **안 보임** → [다시 넣기]로 같은 영상을 넣으면 원래 장면에 그대로 연결 |

- 자동 저장: 내용을 넣으면 1.2초 뒤 저장. 위쪽에 "수정됨 · 곧 자동 저장 / 저장 중… / 자동 저장됨 · 시각 / 저장하지 못했습니다 [다시 저장]" 표시. 저장 전에 창을 닫으면 브라우저가 경고.
- 아무것도 넣지 않은 새 프로젝트는 저장하지 않는다.
- 새로고침·재접속: 마지막으로 연 프로젝트가 자동으로 다시 열린다.
- **내 프로젝트** 탭: 미리보기 그림·제목·길이·디자인·장면 수·영상 수·수정 시각. [열기]로 이어서 편집, [삭제]는 확인 후 문서와 자료 파일(이 기기·Firestore 사진)까지 삭제. [+ 새 프로젝트].
- 자료를 [×]로 빼면 저장된 파일도 지운다.
- 브라우저가 공간 부족 시 마음대로 지우지 않도록 "계속 보관"을 요청한다(지원 브라우저만). 브라우저의 사이트 데이터 삭제를 하면 이 기기의 영상은 지워진다.
- 코드: `src/reels/persist.ts`(자동 저장·열기·새로·삭제), `cloud.ts`(Firestore), `localFiles.ts`(IndexedDB), `pages/reels/ReelProjects.tsx`, `components/reels/SaveIndicator.tsx`.
- 완성한 MP4 파일 자체는 보관하지 않는다(크기 때문). 프로젝트를 열어 [MP4 만들기]로 다시 만든다.
- 테스트(Firestore 대신 브라우저 저장소로 바꿔 확인): 자료 3개·장면 3개 저장 → 새로고침 후 자동 복원(제목·장면·길이·자료) → 목록 표시 → IndexedDB를 비워 다른 기기 흉내: 사진·로고는 복원, 영상 1개는 "이 기기에 없는 자료" → [다시 넣기] 후 저장·다시 열기에서 정상 → 새 프로젝트 → 목록에서 다시 열기 → 삭제 시 사진 데이터까지 삭제. 페이지 오류 0건. **실제 Firestore 저장은 운영 사이트에서 확인 필요.**

## 4단계 (완료) — AI 대본·장면 생성, 붙여넣은 글 다듬기, 장면 AI 다시 쓰기

- 제작 화면 왼쪽 **주제·대본**
  - **브랜드(선택)**: 운영 설정의 브랜드(사이트·설명·규칙)를 AI에 전달. 프로젝트에 `brandId`로 저장.
  - **[✨ 주제로 AI 대본·장면 만들기]**: 영상 길이별 장면 수(10초 4개·15초 5개·30초 8개·60초 12개)로 자막·장면 길이·효과(반짝임·불꽃·강조 박스·가격표·CTA)·가격표·CTA 문구를 만들고, 사진·영상을 순서대로 배정. 제목이 "새 릴스"면 AI 제목으로 바꿈. 대본 칸도 장면 자막으로 채움.
  - **[✨ AI로 다듬기]**: 대본 칸에 붙여넣은 글(3,000자까지)을 같은 장면 수의 릴스 대본으로 다시 씀(글에 있는 사실만).
  - **[장면 나누기]**: AI 없이 쓴 그대로 나눔(기존).
  - **[↩ AI로 바꾸기 전으로 되돌리기]**: 바로 전 상태(제목·대본·장면)로.
- 아래 장면 설정의 **[✨ AI로 다시 쓰기]**: 그 장면 자막만 앞뒤 흐름에 맞게 새로. 요청(예: 더 짧게, 질문으로) 입력 가능. [↩ 이전 자막으로 되돌리기].
- 안전장치(`shared/reelScript.ts`의 `finalizeReelScript`, 서버·로컬 공통): 이모지·해시태그 제거, 자막 최대 2줄, **주제·원문·브랜드 설명에 없는 가격은 가격표에서 삭제**, CTA는 마지막 장면에만, 장면 길이 1~8초.
- **AI 연결 (설정 탭)** — 이 기기에만 저장(localStorage `snsroom.reels.ai`, 비밀값 없음)
  - 서버 AI(기본): `POST /.netlify/functions/reel-script` → OpenAI(JSON 스키마). 관리자 토큰 검증, 키는 Netlify 환경변수에만. 25초 제한.
  - 로컬 AI: Ollama·LM Studio 등 OpenAI 호환 주소(`/v1/models`로 연결 확인·모델 선택, `/v1/chat/completions` 호출). 브라우저가 직접 이 PC의 프로그램에 연결 → 사용료 없음. 형식 지정(json_schema)을 모르면 형식 없이 다시 요청하고 응답 속 JSON을 꺼내 읽음. 3분 제한.
  - 로컬 AI 준비: Ollama는 `OLLAMA_ORIGINS=https://snsroom.netlify.app`, LM Studio는 CORS 허용. 모델별 라이선스는 받기 전에 확인(설정 탭에 안내).
  - AI 없이도 대본 직접 입력 + [장면 나누기]로 계속 쓸 수 있음.
- 테스트: 서버 함수(가짜 OpenAI 응답) — 토큰 없음·다른 계정 401, 주제 없음 400, OpenAI 설정 없음 500 안내, 이모지·해시태그·3번째 줄·입력에 없는 가격(5,000원)·중간 장면 CTA 제거, 장면 수 5개로 자름. 브라우저 — 주제 생성(브랜드 전달·장면 5개·가격표 9,900원·제목), 장면 하나 다시 쓰기·되돌리기, 전체 되돌리기, 다듬기, 오류 표시, 로컬 AI 흉내 서버로 연결 확인·모델 목록·형식 없이 재요청·생성, 로컬 AI 꺼짐 안내. 페이지 오류 0건. **실제 OpenAI·실제 Ollama 결과 품질은 운영에서 확인 필요.**

## 5단계 (완료) — 한국어 AI 목소리·배경음악·자막 동기화

- 제작 화면 왼쪽 **목소리·배경음악** 칸 (`components/reels/SoundPanel.tsx`)
  - **AI 목소리로 자막 읽기**: 장면 자막을 나레이션으로 읽는다(줄바꿈은 띄어 읽기).
  - 목소리 7종(여성 4·남성 3), 말투 4종(밝고 경쾌·차분·또박또박 정보·광고처럼), 속도 4단계(느리게·보통·조금 빠르게·빠르게). 선택지는 `shared/reelVoice.ts`.
    - 속도: 기본 모델 `gpt-4o-mini-tts`는 숫자 속도를 지원하지 않아 말투 지시로 요청(정확한 배속 아님, 화면에 안내). `OPENAI_TTS_MODEL`이 `tts-1` 계열이면 숫자 속도를 보낸다.
  - **[▶ 미리 듣기]**: 첫 장면 자막(없으면 예문)을 지금 설정으로 들려줌.
  - **[🎙 음성 만들기]**: 장면마다 음성을 만들고(진행 n/N·멈추기) **장면 길이를 나레이션에 맞춤**(음성 길이 + 앞 0.15초 + 여유 0.45초 비율). 영상 길이보다 길면 경고와 [영상을 N초로 늘리기].
  - "준비된 음성 n/m장면" 표시 — 자막·목소리·말투·속도를 바꾼 장면은 다시 만들어야 함.
  - **자막 동기화**: 장면 길이를 나레이션에 맞추므로 그 장면 자막이 나오는 동안 그 문장을 읽는다. 자막은 장면 설정에서 그대로 고칠 수 있다.
  - **배경음악**: 없음 / 기본 음악(털복이와 같은 직접 합성 우쿨렐레풍 — 외부 음원 아님) / 내 음악 파일(30MB 이하, 이 기기 IndexedDB에만, 짧으면 반복). 음량, **목소리가 나올 때 음악 자동으로 줄이기**(덕킹, 30%로).
- 음성 저장·비용 절약 (`reels/voice.ts`): 같은 자막·목소리·말투·속도면 다시 만들지 않는다. 이 기기 IndexedDB → Firestore `reelVoices/{key}`(다른 기기용, mp3 base64) → 서버 `reel-voice`(OpenAI 사용료) 순서로 찾는다.
- 소리 합치기 (`reels/sound.ts`): 장면 시작 0.15초 뒤에 그 장면 음성(앞뒤 무음 제거), 음악·덕킹, 최대 크기 제한. 미리보기(`reels/previewAudio.ts`, 재생 시계에 맞춰 재생·위치 이동·구간 반복 따라감)와 MP4가 같은 결과를 쓴다.
- MP4: 화면 + 소리(AAC 우선, 안 되면 Opus). 소리를 넣을 수 없는 브라우저면 소리 없이 만들고 안내. 음성이 없는 장면·이 기기에 없는 음악 파일은 안내.
- 목소리를 켜면 영상 왼쪽 위에 **"AI 음성"** 표시(OpenAI 음성 이용 조건: 듣는 사람에게 AI 음성임을 알림).
- 넣은 영상 자료 자체의 소리는 쓰지 않는다.

- 같은 문장의 음성은 한 번만 만든다(이 화면을 연 동안 메모리에 보관) → 미리보기 후 MP4를 만들어도 음성 비용이 다시 들지 않는다.
- 입력값(상호·디자인·주제·문구·소리 설정)은 이 기기 localStorage `snsroom.tteolbok`에 기억한다.
- 화면 그리기: `src/tteolbok/render.ts`의 `drawTteolbokFrame(ctx, frame, t)` — 릴스와 같이 **시간만으로** 그린다.

### 음성 라이선스
- **OpenAI 음성(TTS)**: 상업 이용 가능. 단 OpenAI 이용 정책상 **듣는 사람에게 AI 음성임을 알려야 한다** → 영상 오른쪽 위 "AI 음성" 표시(기본 켜짐). 끄면 게시글 본문에 적는다.
- 채팅에서 시험 제작한 영상에 쓴 오픈소스 한국어 음성(mimic3 `ko_KO-kss_low`)은 학습 데이터(KSS)가 **CC BY-NC-SA 4.0(비상업)** 이라 매장 홍보에 쓸 수 없어 이 기능에는 넣지 않았다.

### 테스트 (2026-10-22, 이 개발 환경)
- `npm run build` 통과. 디자인 3종 × 등장 전·중·완성 화면 확인, 긴 문구 자동 축소, 빈 줄 처리.
- 시험 음성 3구간으로 MP4 제작: 11.9초 영상을 8초 만에 완성, 1080×1920·30fps + 소리(이 환경 브라우저는 H.264·AAC 인코딩이 없어 VP9+Opus로 확인). 말하는 구간 입·눈 움직임과 끝난 뒤 웃는 얼굴 확인, 음량 정상(최대 -0.6dB).
- 서버 함수 2개는 OpenAI 응답을 흉내 내 확인: 요청 형식·JSON 스키마, 이모지·해시태그·별표 정리, 빈 주제 거절.
- **남은 확인**: OpenAI 키로 실제 문구·음성 생성, 실제 크롬·엣지에서 H.264+AAC MP4, Firestore 상호 저장.

## 핵심어 타이포 (2026-10-22, 디자인 탭 교체)

사용자 요청으로 **디자인 탭의 5종 비교 화면을 지우고** 그 자리에 **핵심어 타이포** 탭(`/reels/keyword`, 예전 주소 `/reels/designs`는 자동 이동)을 넣었다.
기존 5종 템플릿(`src/reels/templates.ts`)은 자동 릴스 제작 화면과 저장된 프로젝트에서 그대로 쓴다(사용자 결정: 디자인 탭에서만 빼기).

글자만 나오는 세로 숏폼. 장면마다 핵심어가 **한 글자씩 3D 입체로** 세워지고 → 작아지며 좌우로 천천히 기울고 → 아래로 문장이 단어 단위로 올라온다.

| 항목 | 내용 |
| --- | --- |
| 상호 | 털복이 숏폼과 같은 목록(Firestore `settings/tteolbok`), 하단에 처음부터 고정·음성 없음. [상호 관리] 공용 컴포넌트 `components/reels/StoreManager.tsx` |
| 디자인 4안 | 흰 바탕(검정 글씨·노란 입체) · 검은 바탕(흰 글씨·빨간 입체) · 빨간 바탕(크림 글씨·갈색 입체) · 모눈 메모지(손글씨 문장) |
| 장면 | 2~5개. 주제 → `keyword-copy`(OpenAI)가 장면별 핵심어(5자 이하)·문장(28자 이하, `*강조*` 1개)을 쓴다. 직접 수정·추가·삭제·순서 변경 |
