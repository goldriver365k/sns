# AI 콘텐츠 매니저 — 프로젝트 지시서 (기준 문서)

이 문서는 이 프로젝트의 기준 문서다. 작업을 시작하기 전에 끝까지 읽고, 모든 작업은 이 문서를 따른다.
기존에 ChatGPT로 만든 사이트(snsroom.goldriver365.chatgpt.site)를 **Firebase + Netlify 기반으로 새로 구축**하는 프로젝트다.

---

## 0. 작업 원칙

- 기획만 하고 끝내지 말고, 실제로 작동하는 웹사이트를 단계별로 완성한다. (진행 순서는 12번)
- 각 단계가 끝나면 무엇을 만들었는지, 어떻게 확인하는지, 다음 단계가 무엇인지 짧게 보고하고 다음 단계로 넘어간다.
- Firebase 프로젝트 생성, API 키 입력, 결제 플랜 변경, Netlify 연결처럼 **사용자가 직접 해야 하는 일은 단계별로 명확히 안내하고 완료를 확인받은 뒤** 진행한다.
- 사용자는 이미 여러 Firebase 프로젝트와 Netlify 사이트를 운영 중이다. **이 프로젝트 전용 Firebase 프로젝트와 Netlify 사이트를 새로 만들고, 기존 프로젝트·사이트는 절대 수정하거나 삭제하지 않는다.**
- 외부 연결이 막히면 만들 수 있는 부분부터 진행하고, 완료된 기능과 남은 작업을 구분해서 보고한다.
- 화면 문구, 주석, 보고는 모두 한국어로 한다.
- 의존성은 꼭 필요한 것만 쓴다.

## 1. 프로젝트 목표

관리자 1명(본인)이 쓰는 비공개 웹사이트. 이름은 **AI 콘텐츠 매니저**.

두 가지 방식으로 SNS 콘텐츠를 만든다.

1. **SNS 게시물 만들기 (수동)**: 원하는 내용을 입력하고 [자동 완성]을 누르면 바로 생성한다. → 4번
2. **매일 자동 생성**: 매일 한국시간 오전 5시에 9개 채널 콘텐츠를 자동 생성해 저장한다. → 5번

결과 형식은 SNS 종류에 따라 다르다.

- **인스타그램 → 카드 이미지** (1080×1350px PNG 3장 + 캡션)
- **스레드 → 문장 원고** (복사 버튼 한 번으로 스레드에 바로 붙여넣기)

**SNS 자동 게시는 하지 않는다.** 관리자가 검토하고 직접 게시한다.
Canva 연동은 하지 않고, 자체 카드 편집기를 만든다.

## 2. 기술 스택

- 프론트엔드: Vite + React + TypeScript
- 스타일: Tailwind CSS
- 인증: Firebase Authentication (Google 로그인, 허용된 관리자 이메일만 접근)
- 데이터베이스: Cloud Firestore
- 파일 저장: Firebase Storage (업로드 사진 원본, 완성 카드 PNG)
- 서버 기능: Netlify Functions (OpenAI 호출은 반드시 서버에서만)
- 예약 실행: Netlify Scheduled Functions — 매일 20:00 UTC (= 한국시간 05:00)
- AI: OpenAI API (모델명은 환경변수 `OPENAI_MODEL`로 지정, 코드에 고정하지 않는다)
- 최신 이슈 수집: 뉴스·검색 API (후보를 비교해 제안하고 사용자 승인 후 연결)
- 카드 PNG 출력: 브라우저에서 캔버스로 렌더링 (폰트 로딩 완료 후 출력)
- ZIP 다운로드: JSZip
- 배포: GitHub(goldriver365k) 저장소 → Netlify 자동 배포

### 실행 시간 제한 주의
Netlify 함수에는 실행 시간 제한이 있다. 9개 채널을 한 번에 생성하면 초과할 수 있으므로,
예약 함수는 **채널별 생성 작업을 나눠서** 처리하고, 각 작업의 상태(대기/진행/완료/실패)를 Firestore에 기록한다.
그래도 제한에 걸리면 대안(Firebase Cloud Functions 등, 유료 플랜 필요 여부 포함)을 비교해 사용자에게 제안한다.

### 환경변수 (Netlify에만 저장, 클라이언트에 노출 금지)
- `OPENAI_API_KEY`
- `OPENAI_MODEL`
- `NEWS_API_KEY` (선택한 뉴스 API)
- `FIREBASE_SERVICE_ACCOUNT` (서버에서 Firestore 쓰기용)
- `ADMIN_EMAILS` (접근 허용 이메일, 기본값: higidia@gmail.com)
- (선택) `OPENAI_TTS_MODEL`, `OPENAI_TTS_VOICE` — 털복이 숏폼 음성. 비우면 `gpt-4o-mini-tts` / `coral`. `OPENAI_TTS_MODEL`은 자동 릴스 나레이션에도 쓰인다(목소리는 화면에서 고름)

> 구현 메모: 브라우저용 Firebase 웹 앱 설정값(`VITE_FIREBASE_*`)과 `VITE_ADMIN_EMAILS`는 공개되어도 되는 값이라
> 클라이언트 빌드에 포함된다. 비밀값에는 절대 `VITE_` 접두사를 쓰지 않는다. (`.env.example` 참고)

## 4. SNS 게시물 만들기 (메인 화면)

2단 레이아웃: **왼쪽 입력 폼 / 오른쪽 결과**. 모바일에서는 입력 폼 아래에 결과를 배치한다.

### 왼쪽 입력 폼 (위에서 아래 순서)
> 사용자 요청으로 변경: 첫째 칸 SNS, 둘째 칸 브랜드, 셋째 칸 브랜드의 주간·월간 계획. 둘째·셋째 칸은 화면에서 수정·추가할 수 있다.

1. **SNS 종류*** (드롭다운): 인스타그램 / 스레드 / 페이스북 / X(트위터) / 틱톡 / 유튜브 쇼츠 / 네이버 블로그 / 카카오톡 채널 / 링크드인
   - SNS마다 내용 구성이 다르다(아래 4-1 표). 고르면 칸 아래에 결과 형태를 보여준다.
2. **브랜드** (드롭다운, 선택): 화산불백 / 후루룩찹찹 / 행복대운 / Hello Korean / 선택 안 함
   - 행복대운 = 5-4의 행운·복·대박 주문 채널.
   - 선택하면 그 브랜드의 규칙(설명, 사이트 주소, 항상 지킬 규칙)을 자동 적용한다.
   - [수정] [+ 추가] 버튼으로 브랜드 이름, 주로 쓰는 SNS, 사이트 주소, 설명, 규칙을 고치거나 새 브랜드를 추가·삭제한다.
   - 브랜드에 주로 쓰는 SNS가 정해져 있고 SNS 종류가 비어 있으면 자동으로 채운다.
3. **콘텐츠 계획** (드롭다운, 선택): 둘째 칸에서 고른 브랜드의 주간 계획·월간 계획 목록
   - 브랜드를 고르면 오늘 요일의 주간 계획이 기본 선택된다. "계획 없이 직접 입력"도 고를 수 있다.
   - [계획 편집] 버튼으로 주간(요일별)·월간(1주차, 15일 등 자유 입력) 계획 줄을 추가·수정·삭제한다.
   - 이 계획은 5번 자동 생성의 주간 편성표와 같은 데이터(`channels`)를 쓴다.
4. **SNS 콘텐츠 내용** (최대 1000자, "0/1000" 글자 수 표시)
   - 계획을 고르지 않았으면 필수, 계획을 골랐으면 선택(비우면 계획 주제에 맞춰 작성).
   - 안내 문구: "SNS에 게시할 콘텐츠의 내용을 간단히 작성해 주세요"
5. **이미지** (선택, 최대 3장) — 사용자 요청으로 추가
   - 넣는 방법: ① 붙여넣기(Ctrl+V / Command+V, 화면 어디서든) ② 끌어다 놓기 ③ [파일 찾기](휴대폰은 갤러리·카메라)
   - ④ [AI로 만들기]는 **사용자 요청으로 보류**(화면에서 숨김). 코드는 남겨 두었고 `ImagePicker.tsx`의 `AI_IMAGE_ENABLED`를 true로 바꾸고 `OPENAI_IMAGE_MODEL`을 설정하면 다시 쓸 수 있다.
   - 인스타그램: 순서대로 카드 1·2·3에 들어간다(‹ › 로 순서 변경). 그 외 SNS: 결과 아래 "함께 올릴 이미지"로 보여주고 [복사](앱에 바로 붙여넣기) [저장](갤러리) 제공.
   - (보류 중) AI 이미지 규칙: 이미지 안에 글자·로고 넣지 않음, 실존 인물·타 브랜드 금지. **음식 브랜드는 실제 메뉴처럼 보이는 음식 완성 사진을 만들지 않고** 분위기·소품·일러스트 위주(5-1 원칙 유지). 메뉴 사진은 직접 찍은 사진을 넣는다.
   - 서버: `/.netlify/functions/image` — 모델은 `OPENAI_IMAGE_MODEL`, 품질은 `OPENAI_IMAGE_QUALITY`(기본 low, 30초 제한 대응). 세로형 SNS는 세로, 블로그·링크드인·페이스북은 가로 이미지.
   - 넣은 이미지는 지금은 이 화면에서만 쓴다(긴 변 2160px로 줄여 사용). 원본 보관·지난 콘텐츠에서 다시 보기는 Storage를 켠 뒤 추가.
6. **언어*** (버튼형, 여러 개 선택 가능): 한국어 / 영어 / 베트남어 / 중국어 / 일본어 / 힌디어
   - 기본값: 한국어. 선택한 언어마다 결과를 따로 만든다.
7. **그 외 지시사항** (선택, 최대 1000자, 글자 수 표시)
   - 안내 문구: "SNS 게시물 작성을 위해 필요한 요청사항을 작성해 주세요"
8. **[자동 완성]** 버튼
   - 필수 항목(*)이 비어 있으면 비활성(회색).
   - 생성 중에는 로딩 표시, 중복 클릭 방지.

### 4-1. SNS 종류별 내용 구성 (사용자 요청: 모든 SNS를 넣고 종류에 맞게 구성)

정의 위치: `shared/sns.ts` — 화면과 서버가 함께 쓴다. 이 표를 바꾸면 그 파일도 함께 고친다.

| SNS | 결과 형태 | 글자 수 제한(경고) | 해시태그(고정 포함) | 구성 |
| --- | --- | --- | --- | --- |
| 인스타그램 | 카드 3장 + 캡션 | **캡션 3줄 이내** (빈 줄 없음, 해시태그 줄 제외) | 3~5 (최대 5개 제한) | 카드: 제목 / 핵심 / 결론·브랜드. 캡션 1줄 키워드 훅 / 2줄 저장·공유 유도 / 3줄 사이트 주소 |
| 스레드 | 글 | 500 | 1~3 | 대화체, 첫 줄 훅 + 짧은 단락 2~4개 + 질문 |
| 페이스북 | 글 | 5000 | 1~3 | 첫 2줄 핵심, 단락 정보 전달, 링크·행동 유도 |
| X(트위터) | 짧은 글 | 140(한글 기준) | 1~2 | 한두 문장, 핵심만 |
| 틱톡 | 영상 대본 + 캡션 | 2200 | 3~5 | 3초 훅, 장면별 대본 4~6개, 행동 유도 |
| 유튜브 쇼츠 | 대본 + 제목 + 설명 | 5000 | 2~3 | 제목 40자 이내, 3초 훅, 장면 4~6개, 설명 2~3줄 |
| 네이버 블로그 | 제목 + 소제목 글 | 10000 | 5~10 | 키워드 제목, 도입, 소제목 3~5개, 요약, [사진: 설명] 자리 표시 |
| 카카오톡 채널 | 메시지 + 버튼 문구 | 400 | 0 | 첫 줄 용건, 혜택·정보 2~3줄, 버튼 문구 제안 |
| 링크드인 | 글 | 3000 | 3~5 | 인사이트, 근거, 제안, 질문으로 마무리 |

- 인스타그램 캡션은 3줄 이내(사용자 요청). 자세한 내용은 카드에 담는다. AI가 넘기면 서버에서 빈 줄을 없애고 첫 줄·저장/공유 유도 줄·사이트 주소 줄을 우선으로 남긴다. 화면에는 "줄 수 n/3"을 표시하고 넘으면 빨간색으로 경고한다.
- 카드 이미지는 인스타그램에서만 만든다. 다른 SNS는 글(텍스트) 결과 + [복사하기].
- 스레드는 게시물당 태그 1개만 주제로 인식하므로 1~3개로 정했다(사용자 확인). 5-3·5-4의 해시태그 개수도 이 표를 따른다.
- 인스타그램은 게시물당 해시태그 최대 5개로 제한되어 기존 "5~10개"를 3~5개로 바꿨다. 5-1의 해시태그 개수도 이 표를 따른다.

### 4-1-1. SNS별 노출 핵심 (사용자 요청: 노출에 가장 중요한 것을 파악해 반드시 반영)

각 SNS에서 추천·검색에 노출되기 위해 가장 중요한 요소를 `shared/sns.ts`의 `essentials`에 정의했다.

1. **생성할 때:** 서버가 이 항목들을 "반드시 지킬 항목"으로 AI에게 전달한다.
2. **생성 후:** `checks`로 자동 검사한다. 통과하지 못한 항목이 있으면 그 항목을 고치도록 한 번 더 생성하고, 결과 화면에 체크리스트(통과/미통과)로 보여준다.
3. **입력 폼:** SNS를 고르면 해당 SNS의 노출 핵심을 미리 보여준다.

| SNS | 노출 핵심 (요약) | 자동 검사 |
| --- | --- | --- |
| 인스타그램 | 캡션 첫 줄 키워드·훅, 저장·공유 유도, 해시태그 3~5, 카드 1장째 큰 제목 | 첫 줄 키워드, 저장·공유 문장, 해시태그 수 |
| 스레드 | 주제 태그 1개, 첫 줄 훅, 답글 부르는 질문, 500자 | 해시태그 수, 질문 마무리, 글자 수 |
| 페이스북 | 첫 2줄 핵심, 댓글 부르는 질문, 해시태그 1~3 | 질문, 해시태그 수 |
| X | 가중치 280 이내, 첫 문장 핵심, 해시태그 1~2, 본문 https 링크 금지 | 길이, 해시태그 수, 링크 |
| 틱톡 | 3초 훅, 키워드를 캡션·자막·말에, 해시태그 3~5, 댓글·저장 유도 | 캡션 키워드, 해시태그 수 |
| 유튜브 쇼츠 | 제목 앞 키워드(40자), 3초 훅, 설명 첫 줄 키워드 + 해시태그 2~3(#Shorts) | 제목 키워드·길이, 해시태그 수 |
| 네이버 블로그 | 제목 앞 키워드, 본문 키워드 3~6회, 1500자 이상 경험·정보, 사진 3장 이상, 소제목 | 제목 키워드, 키워드 횟수, 길이, 사진 자리 |
| 카카오톡 채널 | (광고) 표기 + 무료 수신거부(법적 의무), 첫 줄 용건, 버튼 1개, 해시태그 없음 | (광고), 수신거부, 버튼 |
| 링크드인 | 첫 2줄 훅, 질문 마무리, 본문 https 링크 금지, 해시태그 3~5 | 질문, 링크, 해시태그 수 |

- 브랜드 사이트 주소(bulbaek.com, wishanddo.life 등)는 사용자 규칙이므로 항상 넣는다. 다만 X·링크드인처럼 링크가 노출을 줄이는 SNS에서는 `https://` 없이 도메인 글자로만 글 끝에 적는다.
- 플랫폼 정책은 자주 바뀌므로 운영하며 `shared/sns.ts`를 갱신한다.

### 4-2. 고정 해시태그 (사용자 요청: 한 번 정하면 복사할 때 항상 첨부)

- 브랜드마다 **고정 해시태그**를 저장한다(브랜드 [수정] 창에서 입력, `#`는 빼도 되고 띄어쓰기·쉼표로 구분).
- [복사하기]를 누르면 **본문 + 생성된 해시태그 + 고정 해시태그**가 항상 함께 복사된다. 화면에 보이는 원고를 고쳐도 고정 해시태그는 복사 때 붙는다.
- 고정 해시태그가 가장 먼저 붙고, SNS별 최대 개수(4-1 표)를 넘으면 생성 해시태그부터 뺀다. 고정 해시태그만으로 최대를 넘으면 앞에서부터 최대 개수만 붙이고 입력 폼에 경고한다. 카카오톡 채널은 해시태그를 붙이지 않는다.
- 본문에 이미 들어 있는 해시태그와 중복되면 다시 붙이지 않는다(대소문자 무시). 줄바꿈은 그대로 유지한다.
- 구현: `shared/hashtags.ts`의 `composeCopyText()`. 자동 생성(5번) 결과의 복사에도 똑같이 적용한다.

### 오른쪽 결과 영역
- 생성 전: 가운데에 휴대폰 아이콘과 "클릭 한 번으로 SNS 게시물을 작성해 드려요!" 문구.
- 생성 후: 인스타그램은 6번 형식, 스레드는 7번 형식으로 보여준다.
- 생성 결과는 날짜별로 저장하여 "지난 콘텐츠"에서 다시 볼 수 있게 한다.
- **바로 쓰기** (사용자 요청):
  - 글(스레드 원고, 인스타 캡션)은 생성이 끝나면 바로 클립보드에 복사되고 "복사되었습니다"를 알린다. 브라우저가 자동 복사를 막으면 [복사하기] 버튼 한 번으로 복사한다.
  - 이미지·인스타 카드는 **휴대폰 갤러리에 저장**할 수 있게 한다. 모바일은 공유 시트(Web Share API)의 "이미지 저장"으로 사진 앱에 바로 저장하고, 지원하지 않는 기기·PC는 PNG 파일로 내려받는다. 완성 카드는 앱 안의 이미지 보관함에도 함께 보관한다.

### 5-1. 인스타그램 ① 후루룩찹찹

목적: 브랜드 인지도를 높이고 대학생의 관심과 공감을 얻는다. 음식 홍보만 반복하지 않고, 대학생이 저장·공유하고 싶은 콘텐츠를 함께 만든다.

주간 편성표:

| 요일 | 주제 |
| --- | --- |
| 월 | 메뉴·맛집 소개 |
| 화 | 오늘의 사자성어 |
| 수 | 대학생 관심사 |
| 목 | 인기 메뉴 소개 |
| 금 | 캠퍼스 생활·식사 추천 |
| 토 | 신메뉴·숨겨진 메뉴 |
| 일 | 공감·응원·브랜드 콘텐츠 |

- 사자성어와 대학생 관심사는 각각 주 1회만 만든다.
- 사자성어: 한자·한글 표기, 짧은 뜻풀이, 대학생 일상 예시, 한 줄 응원.
- 대학생 관심사: 시험, 공부, 취업, 자격증, 친구, 생활비, 대학 생활, 식사 등. 검증되지 않은 정보를 사실처럼 쓰지 않고, 최근 주제와 중복을 피한다.
- 카드 구성: 1장 관심을 끄는 제목 / 2장 핵심 내용 또는 공감 메시지 / 3장 결론 또는 브랜드 연결.
- 캡션과 해시태그 5~10개를 함께 생성한다.
- 음식 사진을 AI로 만들거나 실제 메뉴와 다르게 바꾸지 않는다. 사진은 관리자가 직접 넣는다.

### 5-2. 인스타그램 ② 화산불백

- 브랜드 설명: 직화불백덮밥전문점
- 슬로건: **불로 굽고, 밥으로 완성하다**
- 홈페이지: https://bulbaek.com

주간 편성표 (창업 3회, 브랜드 2회, 외식업 정보 2회):

| 요일 | 주제 |
| --- | --- |
| 월 | 음식점 창업 정보 ① |
| 화 | 화산불백 브랜드·메뉴 소개 |
| 수 | 음식점 창업 정보 ② |
| 목 | 외식업 트렌드·상권 분석 |
| 금 | 음식점 창업 정보 ③ |
| 토 | 화산불백 브랜드·창업 소개 |
| 일 | 외식업 운영 팁·자영업 정보 |

- 창업 주제: 창업 준비, 상권·입지, 임대료와 손익분기점, 식재료 원가, 메뉴 개발, 인건비, 주방 효율, 테이블 회전율, 실패 원인, 프랜차이즈 창업, 소규모 음식점 운영.
- 이미 다룬 주제를 다시 만들지 않도록 주제 이력을 저장한다.
- 확인되지 않은 매출, 수익률, 투자비용, 가맹점 수는 절대 만들지 않는다.
- **모든 카드 하단에 `bulbaek.com`을 고정 표시한다.** 디자인을 바꿔도 사라지면 안 된다.
- 캡션에도 `bulbaek.com` 사이트 주소를 넣는다. (사용자 확인: 화산불백 콘텐츠에는 bulbaek.com이 들어간다)
- PNG 다운로드 전에 주소가 보이는지 자동 검사하고, 빠졌거나 잘렸으면 다운로드를 막고 자동 복구한다.

### 5-3. 스레드 ① 오늘의 핵심 키워드 (경제·사회·생활)

- 정치 논쟁보다 생활에 영향을 주는 경제·사회·생활 이슈를 우선한다.
  (경제·금융, 주식시장, 부동산·재건축, 물가, 민생지원 정책, 제도 변화, 생활 경제용어, 소비 트렌드)
- 형식: 키워드 1개, 관심을 끄는 첫 줄, 본문 150~300자, 생활에 미치는 영향, 해시태그 3~5개.
- 뉴스 API로 근거를 수집하고, 출처·발행일·원문 URL을 함께 저장한다(원고에는 넣지 않고 관리자 화면에서만 확인).
- 검색량 데이터 없이 "검색 1위", "실시간 인기 검색어" 같은 표현을 쓰지 않는다.

### 5-4. 스레드 ② 행운·복·대박 주문

- 매일 새로운 행운 주문을 주는 긍정 메시지 콘텐츠.
- 형식: 짧고 따라 읽기 쉬운 주문 문장 + 짧은 응원 메시지 + 해시태그 3~5개.
- 최근 문구와 겹치지 않게 이력을 저장한다.
- **모든 원고에 사이트 주소 `wishanddo.life`를 넣는다.** (사용자 확인) 생성 후 주소가 빠졌으면 자동으로 덧붙인다.
- (그 밖의 상세 규칙은 추가로 받으면 반영한다.)

### 5-5. 스레드 ③ Hello Korean (5개 언어)

- 무료 한글 학습 사이트 Hello Korean을 홍보한다. 사이트 주소 **hellokorean.site는 캡션·게시물에 반드시 넣는다**(https:// 링크, 코드로 보장 — 사용자 지시 2026-10-22).
- 언어(사용자 지시 2026-10-22): 한국어 + English / 中文 / 日本語 / Tiếng Việt / Bahasa Indonesia — 언어별로 원고 1개씩. (원래 지시서의 힌디어는 선택지로만 남김)
- 단순 번역이 아니라 각 언어 사용자에게 자연스러운 문장으로 쓴다.
- 매일 다른 각도로 소개한다(예: 자모 원리, 발음, 쓰기, 학습 팁 등).
- (원래 지시서의 이 부분 상세 규칙이 누락되어 있음. 사용자에게 추가 규칙이 있는지 확인한다.)

### 5단계 구현 메모 (카드 편집기)

- 여는 법: 인스타그램 결과의 [편집기에서 수정] 또는 카드 미리보기를 누름. 전체 화면, 위에 카드 1·2·3 전환, [완료].
- 그리기 구조: 디자인 = 배경 + 글씨 기본 모양 + **자동 배치** + 꾸밈. 편집기에서 옮기거나 바꾼 값은 `cards[].overrides`(`shared/cards.ts`: `layout` 위치·크기, `styles` 제목/본문/강조 글씨 모양)에 저장되고, 있으면 자동 배치 대신 쓴다. 미리보기와 PNG는 같은 함수 → 픽셀 단위로 동일함을 테스트로 확인.
- 직접 조작: 제목·본문·강조 문구·사진을 눌러 고르고 끌어서 이동, 오른쪽 아래 동그라미로 크기 조절(마우스·터치). 사진은 [사진 자리 옮기기] / [사진 자르기(안에서 이동)] + 확대(1~3배).
- 글씨: 제목·본문·강조 각각 폰트(5종)·굵기·크기·색상·정렬·줄 간격. 상자에 안 들어가면 최소 크기까지 자동 축소.
- 사진 넣기 4가지: 파일 찾기 / 미리보기에 끌어다 놓기 / Ctrl+V 붙여넣기 / **보관함**에서 선택. 보관함은 지금은 "이번 작업에서 넣은 사진"(입력 폼 + 편집기 공용, 최대 10장)이며, 8단계 이미지 보관함(Storage)과 연결한다. 사진을 넣거나 바꾸면 배치는 자동으로 다시 계산(글씨 모양은 유지)해 사진이 글을 덮지 않게 한다.
- 디자인을 바꾸면 글·사진은 유지, 위치·글씨 모양은 새 디자인 기본값. [이 카드 배치 초기화]로 되돌림.
- 하단 주소 자리는 점선으로 표시되며 옮길 수 없다. 저장 전 검사에 "카드 밖으로 나간 요소"도 추가.
- 편집 내용은 결과와 함께 자동 저장(Firestore). 이미지 파일 자체는 Storage를 켜기 전까지 저장되지 않는다.

### 카드 편집기 (가장 중요한 기능)
**사진은 관리자가 직접 넣고, 제목과 본문을 입력하면 글씨가 카드에 자동 배치되는 편집기.**

- 왼쪽: 브랜드 선택, 디자인 5종, 제목·본문·강조 문구 입력, 폰트·색상 설정, 이미지 넣기
- 가운데: 1080×1350 비율 미리보기. 글씨와 사진을 직접 선택해 이동·크기 조절
- 아래: 카드 1·2·3 전환, 저장, 다운로드, 전체 ZIP 다운로드

이미지 넣는 방법 4가지 모두 지원:
1. 파일 선택
2. 드래그 앤 드롭
3. Ctrl+V / Command+V 붙여넣기
4. 이미지 보관함에서 선택

- 사진 확대·축소, 위치 이동, 자르기 가능. 원본은 Storage에 별도 보관.
- 입력한 글씨는 미리보기에 즉시 반영. 길어지면 자동 줄바꿈, 필요하면 글씨 크기 자동 축소.
- 제목·본문 각각 폰트, 크기, 굵기, 색상, 정렬, 줄 간격 변경 가능.
- 사진이 없어도 디자인 배경색과 글씨만으로 카드가 완성되어야 한다.
- 출력 검사: 한글 깨짐, 글씨 잘림, 화산불백 주소 누락을 다운로드 전에 확인한다.
- 미리보기와 실제 PNG가 일치해야 한다(PC와 모바일 모두).

- 글자 수를 표시하고, 스레드 제한(500자)을 넘으면 빨간색으로 경고한다.
- 원고는 그 자리에서 직접 수정할 수 있고, 수정한 내용이 복사된다. 수정 내용은 자동 저장한다.
- 여러 언어 결과는 언어 탭으로 전환하고, 탭마다 [복사하기] 버튼을 둔다.
- 버튼: [승인] [다시 생성]

### 배경 제거 방식 (`src/photo/removeBg.ts`)

- 브라우저 안에서 AI 모델을 돌린다(서버·API 비용 없음, 사진이 밖으로 나가지 않음).
- 모델: `BritishWerewolf/IS-Net` — rembg의 isnet-general-use(원본 xuebinqin/DIS). **Apache-2.0**(상업 이용 가능). 처음 한 번 약 170MB를 Hugging Face에서 받아 브라우저 저장소(Cache API)에 두고, 이후 바로 쓴다. 처음 쓰는 기기는 [배경 제거 시작]으로 한 번 확인받는다(받은 기록: localStorage `snsroom.photo.modelReady`).
- 실행: `@huggingface/transformers`(onnxruntime-web)로 CPU(WASM)에서 1024×1024 입력 → 마스크. 이 화면에 들어올 때만 라이브러리를 내려받는다(다른 화면 속도 영향 없음). onnxruntime 실행 파일(약 21MB)은 사이트에서 직접 제공.
- 처리 시간(테스트 환경 CPU): 1장 약 13~24초. 일반 PC는 더 빠르다.
- 검토 후 쓰지 않은 모델: BiRefNet lite(MIT) — 품질은 좋지만 CPU(WASM)에서 메모리 부족으로 실행되지 않아 그래픽카드(WebGPU)가 있는 기기에서만 가능. RMBG-1.4/2.0 — 상업 이용 제한 라이선스. ISNet-ONNX(onnx-community)·@imgly — AGPL.
- (다음 단계 후보) 브랜드 로고·사이트 주소 넣기, 결과를 SNS 게시물·카드 편집기 사진으로 바로 보내기, 만든 AI 배경 보관, 그래픽카드 가속.

### 8단계 구현 메모 (나머지 화면 1~3)

- **오늘의 콘텐츠**: 자동 생성 보류 중이라 오늘(KST) 만든 콘텐츠를 모아 보여준다. 요약(오늘 수·검토 대기·승인 완료) + 펼쳐서 복사·수정·승인·삭제.
- **지난 콘텐츠**: 최근 순 30개씩 [더 보기], 날짜 선택(주소 `?date=yyyy-mm-dd`), 브랜드·SNS 거르기, 날짜별 묶음. 펼치면 생성 직후와 같은 결과 화면(복사, 직접 수정 + 1초 뒤 자동 저장, 승인, 카드 디자인·편집기·PNG/ZIP). [다시 생성]은 없음. 삭제 가능.
- **콘텐츠 캘린더**: 월 단위(월요일 시작), 날짜별 콘텐츠(승인=진한 초록), [계획 표시]로 고른 브랜드의 주간(요일)·월간("15일"처럼 날짜가 적힌 것) 계획 주제 표시. 날짜를 누르면 지난 콘텐츠의 그 날짜로 이동. 모바일은 개수만 표시.
- **운영 설정**: 브랜드 관리(목록, 순서 바꾸기, 수정, 계획 편집, 추가·삭제) + 서버 연결 점검 + 자동 생성(보류) 안내.
- 조회는 별도 색인이 필요 없도록 `createdAt` 정렬 또는 `date` 범위 한 가지 조건만 쓰고, 브랜드·SNS 거르기는 화면에서 한다.
- 이미지 보관함(4번)은 Firebase Storage가 필요해 사용자 결정 후 진행.

## 8. 데이터 구조 (Firestore 초안)

구현하면서 필요에 따라 조정하되, 변경 시 이 문서에 반영한다.

- `channels/{channelId}` — 브랜드(채널) 설정. 처음 실행 시 화산불백·후루룩찹찹·행복대운·Hello Korean 기본값을 넣는다.
  - `name`, `sns`(4-1의 SNS 값 또는 빈 값), `siteUrl`, `description`, `rules`, `order`
  - `hashtags[]` — 고정 해시태그(복사 시 항상 첨부, 4-2)
  - `plans[]` — `{ id, period: 'weekly'|'monthly', when(요일 또는 자유 입력), topic }`
  - (6단계에서 추가 예정) 켜기/끄기, 기본 디자인
- `settings/app` 의 `channelsSeeded` — 기본 브랜드를 이미 넣었는지 표시(모두 지운 뒤 다시 생기지 않게)
- `contents/{contentId}` — 생성 결과
  - `date`, `channelId`, `snsType`(instagram/threads), `source`(auto/manual), `status`(draft/approved/archived)
  - 인스타: `cards[3]`(제목, 본문, 강조 문구, 디자인, 폰트·색상·위치, 이미지 경로), `caption`, `hashtags`
  - 스레드 등 글 결과: `posts[]`(언어, 본문, 글자 수)
  - `references[]`(출처, 발행일, URL), `topic`, `createdAt`, `updatedAt`
  - (구현) 수동 생성 문서 필드: `imageIds[]`, `date`(KST yyyy-mm-dd), `channelId`, `brandName`, `snsType`, `source: 'manual'`, `status`, `topic`, `fixedHashtags[]`, `input{content, instructions, languages[]}`, `posts[]{language, keyword, title, body, hashtags[], cards[]}`, `createdAt`, `updatedAt`
  - (구현) `posts[].hashtags`는 생성 해시태그만 저장하고, 고정 해시태그는 `fixedHashtags`에 따로 둔다. 복사할 때 `composeCopyText()`로 합친다.
- `topicHistory/{id}` — 채널별 다룬 주제 이력(중복 방지)
- `jobs/{jobId}` — 자동 생성 작업 상태와 오류 기록
- `images/{imageId}` — 사진 저장소(구현): `data`(JPEG data URL, 긴 변 1600px, 900KB 이하로 품질 자동 조정), `width`, `height`, `source`, `createdAt`
  - Firebase Storage(유료 요금제 필요할 수 있음) 대신 Firestore에 저장해, PC에서 넣은 사진을 휴대폰에서도 본다(사용자 문제 제기: PC에서 만든 카드를 휴대폰에서 열면 사진이 없음).
  - 사진은 넣는 즉시 저장된다(입력 폼·카드 편집기 모두). 콘텐츠 문서의 `imageIds[]`에 순서를 기록하고, 카드별 선택은 `cards[].imageId`.
  - 지난 콘텐츠·오늘의 콘텐츠에서 항목을 펼칠 때 사진을 불러온다. 원본 해상도 보관이나 대용량이 필요해지면 Storage로 옮긴다.
- `settings/app` — 생성 시간, 관리자 이메일 등
- `settings/tteolbok` — 털복이 숏폼 하단 상호 목록(구현): `stores[]{ id, name, loc, bg, fg }`, `updatedAt`. 문서가 없으면 기본 목록(후루룩찹찹 모인관 2층·밥심·만권화밥·두꺼비 종합분식·화산불백)을 보여 주고, [상호 관리]에서 저장할 때 만든다. 상세: docs/REELS.md
- `reelProjects/{id}` — AI 자동 릴스 프로젝트(구현, 상세: docs/REELS.md)
  - `title`, `topic`, `script`, `duration`(10|15|30|60), `template`, `scenes[]`, `logoId`, `showProgress`, `thumbnail`(목록용 216×384 JPEG data URL), `createdAt`, `updatedAt`
  - `assets[]` — 자료 정보만: `{ id, kind(media|logo|character), type(image|video), name, width, height, duration?, keyModel?, cloud? }`
  - 자료 파일: 이 기기 브라우저 저장소(IndexedDB `snsroom-reels`/`files`, 키 = 자료 id)에 원본. 사진·로고·캐릭터는 `images/{자료 id}`에도 저장(`source: 'reel'`, 투명 배경 PNG는 PNG로 크기만 줄임) → `cloud: true`. 영상은 이 기기에만 저장(사용자 결정: 무료 방식).
  - `audio` — `{ voiceOn, voice, style, speed, music('none'|'builtin'|'file'), musicFile{id,name}|null, musicVolume(0~1), ducking }`. 내 음악 파일은 이 기기 IndexedDB에만.
  - `brandId` — AI 대본에 반영할 브랜드.
  - `language` — 자막·AI 대본·목소리 언어(기본 ko).
  - `texts[]` — 영상 위에 더 넣은 글자 `{ id, sceneId(null=전체), text, x, y, size, color, font, style }`.
  - `captions` — 언어별 인스타그램 캡션 `{ ko, en, … }`(해시태그·사이트 링크 포함).
  - 편집 내용은 1.2초 멈추면 자동 저장. 마지막으로 연 프로젝트는 다음에 릴스 화면에 들어오면 다시 열린다(localStorage `snsroom.reels.lastProject`).
- `photoDesigns/{id}` — 상품 사진 편집기의 내 디자인(구현): `title`, `originalId`, `maskId`, `aiBg{id, prompt}|null`, `settings`(크기·배경·그림자·여백·직접 입력 크기), `transform{dx, dy, scale, rotate}`, `texts[]{id, text, x, y, size, color, font, bold, box}`, `thumbnail`, `createdAt`, `updatedAt`. 사진은 `images/{id}`(`source`: photo / photo-mask / photo-aibg). 상세: 7-1
- `reelVoices/{key}` — 자동 릴스 나레이션 음성 저장(구현): `data`(mp3 base64), `createdAt`. key는 목소리·말투·속도·글의 해시. 같은 문장을 다시 만들지 않아 비용을 아낀다(이 기기 IndexedDB에도 같은 key로 저장).

## 8-1. 생성 서버 구조 (3단계 구현)

- `POST /.netlify/functions/generate` (`netlify/functions/generate.ts`, 리다이렉트 규칙 영향 없는 기본 주소): 게시물 1개(언어 1개)를 생성한다.
  - Netlify 동기 함수는 **30초 제한**이므로 언어별로 나눠 화면에서 동시에 호출하고, OpenAI 호출은 25초에서 끊고 안내한다.
  - Firebase ID 토큰을 Google 공개 키로 검증(`netlify/lib/auth.ts`, 서비스 계정 불필요) + `ADMIN_EMAILS` 확인 후에만 실행.
  - OpenAI Chat Completions + JSON 스키마(구조화 출력). 모델은 `OPENAI_MODEL`, 추론형 모델이면 선택 설정 `OPENAI_REASONING_EFFORT`(예: low)로 속도를 높인다.
  - 생성 후 코드로 한 번 더 보장: 사이트 주소 누락 시 덧붙임, X·링크드인은 `https://` 제거, 본문 끝 해시태그 줄은 해시태그 칸으로 이동, 고정 해시태그와 중복 제거.
- `POST /.netlify/functions/tteolbok-copy` / `tteolbok-voice`: 털복이 숏폼 문구(JSON 스키마)·한국어 AI 음성(mp3). 같은 관리자 토큰 검증. 상세: docs/REELS.md
- `POST /.netlify/functions/reel-script`: 자동 릴스 대본(mode: topic 주제로 새로 / rewrite 붙여넣은 글 다듬기 / scene 장면 하나 다시 쓰기, JSON 스키마). 같은 관리자 토큰 검증. 안내문·정리 규칙은 `shared/reelScript.ts`(로컬 AI도 같은 규칙). 상세: docs/REELS.md
- `POST /.netlify/functions/reel-voice`: 자동 릴스 장면 나레이션(mp3 base64). `{ text(200자), voice, style, speed }`, 선택지는 `shared/reelVoice.ts`. 같은 관리자 토큰 검증. 모델은 `OPENAI_TTS_MODEL`(기본 gpt-4o-mini-tts).
- `POST /.netlify/functions/bg-search`: 배경용 무료 사진 찾기(`{ q, page }`)·받기(`{ imageId }`, base64). Openverse CC0·퍼블릭 도메인만. 같은 관리자 토큰 검증. 상세: 7-1
- `POST /.netlify/functions/keyword-copy`: 핵심어 타이포 장면 문구(주제 → 장면별 핵심어·문장, JSON 스키마). 같은 관리자 토큰 검증. 상세: docs/REELS.md
- `GET /.netlify/functions/health`: 관리자 토큰 확인 후 환경변수 유무만 알려준다(값 비공개). 운영 설정의 [서버 연결 점검]에서 사용.
- 오류 메시지에 HTTP 상태와 OpenAI가 알려준 원인을 함께 표시한다(관리자 전용 화면).
- 화면: 결과를 노출 검사(`checkReach`)해서 통과 못 한 항목이 있으면 그 항목을 지정해 1번 더 생성(보완)한다.
- 저장은 화면에서 Firestore에 직접 한다(보안 규칙으로 관리자만 가능). 수정 내용은 입력이 멈추고 1초 뒤 자동 저장.
- 생성이 끝나면 첫 언어 결과를 자동 복사하고, 브라우저가 막으면 [복사하기] 안내.

## 9. 보안

- OpenAI·뉴스 API 키는 Netlify 환경변수에만 둔다. 클라이언트 코드와 저장소에 절대 넣지 않는다.
- `.env`는 `.gitignore`에 추가하고, 예시는 `.env.example`로만 제공한다.
- Firestore·Storage 보안 규칙: 허용된 관리자 이메일만 읽기·쓰기.
- Netlify Functions는 Firebase ID 토큰을 검증한 뒤에만 실행한다.
- 예약 함수는 외부에서 임의 호출할 수 없게 한다.

## 10. 오류 처리

- AI 생성 실패 시 해당 채널만 실패로 표시하고 [다시 시도] 버튼을 제공한다. 다른 채널은 계속 진행한다.

각 단계 완료 후 보고하고 다음으로 넘어간다.

1. **준비**: 저장소 생성(GitHub goldriver365k), Vite + React + TS 프로젝트, 폴더 구조. 사용자에게 새 Firebase 프로젝트 생성과 Netlify 연결 방법 안내.
2. **로그인과 기본 레이아웃**: Firebase Auth, 관리자 이메일 제한, 왼쪽 메뉴, 빈 화면들.
3. **SNS 게시물 만들기 — 스레드**: 입력 폼, Netlify Function으로 OpenAI 호출, 텍스트 결과와 복사 기능, 저장.
4. **SNS 게시물 만들기 — 인스타그램**: 카드 3장 생성, 디자인 5종, PNG·ZIP 다운로드, 캡션 복사.
5. **카드 편집기**: 사진 넣기 4가지, 글씨 자동 배치·수정, 화산불백 주소 검사.
6. **채널 설정과 자동 생성**: 채널·편성표 설정, 채널별 생성 규칙, 주제 이력, 예약 함수, 작업 상태 기록.
7. **오늘의 콘텐츠 보드**: 요약 카드, 필터, 승인 처리, Hello Korean 언어 탭 묶음.
8. **나머지 화면**: 콘텐츠 캘린더, 이미지 보관함, 지난 콘텐츠, 운영 설정.
9. **뉴스 API 연결**: 후보 비교 후 사용자 승인, 핵심 키워드 채널에 적용.
10. **보안·오류 처리 점검, 11번 완료 기준 전체 테스트, 배포 및 운영 안내.**
