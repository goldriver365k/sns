# AI 자동 릴스 — 개발 문서

기존 SNSROOM에 추가한 메뉴. 주제·대본·사진·영상으로 1080×1920 세로 릴스를 구성한다.
기존 기능·디자인은 그대로 두고 `src/reels/`, `src/components/reels/`, `src/pages/reels/`에만 추가했다.

## 1단계 (완료) — 메뉴, 제작 화면, 업로드, 타임라인, 디자인 5종, 모션그래픽 미리보기

### 화면 그리기 구조
- `src/reels/render.ts`의 `drawReelFrame(ctx, project, t)` — **t초의 화면을 시간만으로 그린다**(난수도 장면 id로 고정). 그래서 다음 단계 MP4 제작 때 같은 함수로 프레임을 하나씩 뽑으면 미리보기와 같은 영상이 된다.
- 미리보기는 1080×1920 캔버스를 화면에 맞춰 줄여 보여 준다. 영상 자료는 지금 장면일 때만 재생 위치를 맞춰 돌린다(소리 없음).

### 아직 없는 것 (화면에 "다음 단계"로만 안내, 작동하는 척하지 않음)
AI 대본·장면 생성과 재작성, 장면 AI 재생성, 한국어 AI 목소리, 배경음악, 음성 동기화 자막. (프로젝트 저장은 3단계에서 완료)

## 2단계 (완료) — MP4 제작·다운로드 (사용자 PC에서 처리)

- 오른쪽 **MP4 만들기**: 1080×1920, 30fps, 선택한 길이(10·15·30·60초). 진행 막대·취소 → 완성 영상 바로 재생 → [MP4 다운로드], 휴대폰은 [휴대폰에 저장·공유].
- 방식: 미리보기와 같은 `drawReelFrame`으로 한 프레임씩 그려 브라우저 WebCodecs로 인코딩, `mp4-muxer`로 MP4 포장(`src/reels/exporter.ts`). 서버로 보내지 않음 → 서버 비용 0.
- 코덱: **H.264를 먼저**(High → Main → Baseline). H.264 인코딩이 없는 브라우저는 VP9 방식 MP4로 만들고 경고를 보여 준다. 둘 다 안 되면 "PC의 크롬·엣지에서 열어 주세요" 안내.
- 영상 자료는 프레임마다 정확한 위치로 맞춘 뒤 그린다. 만드는 동안 미리보기는 영상 위치를 건드리지 않는다.
- 지금은 소리 없는 영상(목소리·음악은 다음 단계).
- 테스트(이 개발 환경의 브라우저는 H.264 인코딩이 없어 VP9로 확인): 10초 릴스(사진·영상·로고·반짝임·가격표·CTA) → 18초 만에 6MB MP4, ffprobe로 1080×1920·30fps·300프레임·10.0초 확인. 같은 시각의 미리보기와 MP4 프레임 평균 차이 약 2/255(압축 차이). 취소 동작 확인. **H.264 결과물은 실제 크롬·엣지에서 확인 필요.**

## 3단계 (완료) — 프로젝트 자동 저장·다시 편집

영상 저장 방식은 사용자가 **"이 기기 브라우저 안에 저장(무료)"**으로 결정(2026-10-21). 유료 서비스 없음.

| 무엇 | 어디에 | 다른 기기에서 |
| --- | --- | --- |
| 제목·주제·대본·장면·길이·디자인·로고 지정 | Firestore `reelProjects/{id}` | 보임 |
| 목록용 작은 미리보기 그림 | 같은 문서 `thumbnail` | 보임 |
| 사진·로고·캐릭터 | 이 기기 IndexedDB(원본, 긴 변 2160px) + Firestore `images`(긴 변 1600px 이하, 투명 배경 유지) | 보임(1600px 판) |
| 영상 | 이 기기 IndexedDB만 | **안 보임** → [다시 넣기]로 같은 영상을 넣으면 원래 장면에 그대로 연결 |

- 자동 저장: 내용을 넣으면 1.2초 뒤 저장. 위쪽에 "수정됨 · 곧 자동 저장 / 저장 중… / 자동 저장됨 · 시각 / 저장하지 못했습니다 [다시 저장]" 표시. 저장 전에 창을 닫으면 브라우저가 경고.
- 아무것도 넣지 않은 새 프로젝트는 저장하지 않는다.
- 새로고침·재접속: 마지막으로 연 프로젝트가 자동으로 다시 열린다.
- **내 프로젝트** 탭: 미리보기 그림·제목·길이·디자인·장면 수·영상 수·수정 시각. [열기]로 이어서 편집, [삭제]는 확인 후 문서와 자료 파일(이 기기·Firestore 사진)까지 삭제. [+ 새 프로젝트].
- 자료를 [×]로 빼면 저장된 파일도 지운다.
- 브라우저가 공간 부족 시 마음대로 지우지 않도록 "계속 보관"을 요청한다(지원 브라우저만). 브라우저의 사이트 데이터 삭제를 하면 이 기기의 영상은 지워진다.
- 코드: `src/reels/persist.ts`(자동 저장·열기·새로·삭제), `cloud.ts`(Firestore), `localFiles.ts`(IndexedDB), `pages/reels/ReelProjects.tsx`, `components/reels/SaveIndicator.tsx`.
- 완성한 MP4 파일 자체는 보관하지 않는다(크기 때문). 프로젝트를 열어 [MP4 만들기]로 다시 만든다.
- 테스트(Firestore 대신 브라우저 저장소로 바꿔 확인): 자료 3개·장면 3개 저장 → 새로고침 후 자동 복원(제목·장면·길이·자료) → 목록 표시 → IndexedDB를 비워 다른 기기 흉내: 사진·로고는 복원, 영상 1개는 "이 기기에 없는 자료" → [다시 넣기] 후 저장·다시 열기에서 정상 → 새 프로젝트 → 목록에서 다시 열기 → 삭제 시 사진 데이터까지 삭제. 페이지 오류 0건. **실제 Firestore 저장은 운영 사이트에서 확인 필요.**

## 털복이 숏폼 (2026-10-22 추가)

AI 자동 릴스 안의 **털복이 숏폼** 탭(`/reels/tteolbok`). 상호를 고르고 디자인을 고른 뒤 주제만 넣으면 문구 → 음성 → 영상까지 자동으로 만든다.
기존 릴스 기능은 건드리지 않고 `src/tteolbok/`, `src/pages/reels/TteolbokStudio.tsx`, 서버 함수 2개만 추가했다(릴스의 `pickCodec`만 재사용).

| 기능 | 내용 |
| --- | --- |
| 고정 요소 | '털복이' 제목, 털복이 캐릭터(`public/tteolbok/bear.png`, 원래 눈·입을 지운 그림), 이름표 |
| 1. 상호 | 하단에 **첫 화면부터 고정**, 음성으로 읽지 않음. [상호 관리]에서 추가·수정·삭제·색 지정 → Firestore `settings/tteolbok` |
| 2. 디자인 | 말풍선(살구색 단색, 말풍선) · 칠판(분필 글씨가 써지는 효과) · 포스터(빨간 배경, 큰 글씨, 카드). 현재 문구로 그린 썸네일로 비교 |
| 3. 주제 | [문구 자동 작성] → `tteolbok-copy`(OpenAI, `OPENAI_MODEL`). 제목 2줄·포인트·말풍선 3줄을 털복이 말투(해요체)로. 바로 수정 가능, `*단어*` 강조 |
| 4. 소리 | 털복이 AI 음성(`tteolbok-voice`, OpenAI TTS) + 직접 합성한 배경음악(외부 음원 없음). 음성 중엔 음악을 줄인다 |
| 립싱크 | 음성 크기(30fps)로 입을 벌리고, 말하는 동안 눈을 뜨고 깜빡임. 말하지 않을 땐 원래의 웃는 눈·ω 입 |
| 타이밍 | 음성 길이에 맞춰 줄이 등장하고 영상 길이가 정해짐(최소 9초). 긴 줄은 한 줄에 맞게 글씨 자동 축소, 빈 줄은 빠짐 |
| 한 번에 만들기 | 주제가 바뀌었으면 문구 작성 → 음성 → MP4까지 버튼 하나로 |
| MP4 | 브라우저에서 제작(서버 비용 0). 화면 H.264 우선/VP9 대체, 소리 **AAC 우선/Opus 대체**. 다운로드·휴대폰 공유 |

- 같은 문장의 음성은 한 번만 만든다(이 화면을 연 동안 메모리에 보관) → 미리보기 후 MP4를 만들어도 음성 비용이 다시 들지 않는다.
- 입력값(상호·디자인·주제·문구·소리 설정)은 이 기기 localStorage `snsroom.tteolbok`에 기억한다.
- 화면 그리기: `src/tteolbok/render.ts`의 `drawTteolbokFrame(ctx, frame, t)` — 릴스와 같이 **시간만으로** 그린다.

### 음성 라이선스
- **OpenAI 음성(TTS)**: 상업 이용 가능. 단 OpenAI 이용 정책상 **듣는 사람에게 AI 음성임을 알려야 한다** → 영상 오른쪽 위 "AI 음성" 표시(기본 켜짐). 끄면 게시글 본문에 적는다.
- 채팅에서 시험 제작한 영상에 쓴 오픈소스 한국어 음성(mimic3 `ko_KO-kss_low`)은 학습 데이터(KSS)가 **CC BY-NC-SA 4.0(비상업)** 이라 매장 홍보에 쓸 수 없어 이 기능에는 넣지 않았다.

### 테스트 (2026-10-22, 이 개발 환경)
- `npm run build` 통과. 디자인 3종 × 등장 전·중·완성 화면 확인, 긴 문구 자동 축소, 빈 줄 처리.
- 시험 음성 3구간으로 MP4 제작: 11.9초 영상을 8초 만에 완성, 1080×1920·30fps + 소리(이 환경 브라우저는 H.264·AAC 인코딩이 없어 VP9+Opus로 확인). 말하는 구간 입·눈 움직임과 끝난 뒤 웃는 얼굴 확인, 음량 정상(최대 -0.6dB).
- 서버 함수 2개는 OpenAI 응답을 흉내 내 확인: 요청 형식·JSON 스키마, 이모지·해시태그·별표 정리, 빈 주제 거절.
- **남은 확인**: OpenAI 키로 실제 문구·음성 생성, 실제 크롬·엣지에서 H.264+AAC MP4, Firestore 상호 저장.
